# HDi menu implementation plan

## Goal and definition of done

Add the library and VLC-facing interfaces needed to open, display, and operate the
reference Advanced Content menu while its associated HD DVD title is playing.
"Operate" means that the initial menu is rendered at the correct 1920x1080
coordinates, focus can be moved with the four navigation keys, activated buttons
perform their authored action, the menu can be opened and closed, and its state
stays synchronized with the title clock.  Playback, audio/video decoding, window
management, and final compositing remain VLC responsibilities.

The reference artifact is intentionally not part of the repository:

* URL: `https://litter.catbox.moe/y5vsmchoajfxa9h4.aca`
* SHA-256: `de89cf076bcebe005c4e0d93dcf9f97c18c196fe5cb6fcac83069857f165d699`
* Size: 3,488,246 bytes

Tests which use it must read a path from `HDDVD_REFERENCE_ACA` and skip, rather
than fail, when it is absent.  The archive must never be copied into a source or
build directory, packaged, or committed.

## What the reference menu requires

An inspection with the current ACA reader found 40 CRC-valid members:

* three manifests (`main.xmf`, `playlist.xmf`, and `TopMenu.xmf`), one markup
  document (`main.xmu`), and four compiled scripts;
* 32 PNG resources, including normal and focused button states;
* an HDi application region of 1920x1080;
* absolute layout, image-list style values, nested `div` elements, buttons,
  initial focus, `display`, `zIndex`, and directional navigation properties; and
* authored actions for menu switching, focus changes, playback selection, and
  menu dismissal, which are held in the compiled scripts.

Every member has an `AACS` object envelope.  The XML payload starts around byte
283/286 and is parseable after the envelope is removed; PNG signatures likewise
occur after an envelope.  The current XML dump functions pass the complete member
to libxml2, so `hddvd-menuinfo` stops with `HDDVD_EPARSE`.  Script members use the
binary HDi representation (object type `0x11`) rather than source text.  Treating
them as encrypted blobs or feeding them to a generic JavaScript engine will not
work.  These observations are fixture-specific evidence, not yet a general file
format specification, and must become parser tests before implementation relies
on them.

## Architectural boundary

Keep libhddvd independent of VLC, graphics APIs, audio/video codecs, and a
particular JavaScript engine.  Expose a small, versioned navigation engine that
VLC can drive:

1. a **disc/resource layer** resolves case-insensitive HD DVD URIs and reads
   bounded objects from directories or ACA members;
2. a **depacketizer** validates and removes the `AACS` object envelope, returning
   typed payloads without silently attempting content decryption;
3. **XMF/XMU parsers** build immutable application, scene, style, and timing
   models;
4. an **HDi runtime** owns mutable DOM, focus, timers, script globals, and player
   state;
5. a **renderer-neutral display list** describes image quads, clipping, opacity,
   visibility, and z-order; and
6. a **host callback interface** reports play, seek, playlist/title selection,
   menu visibility, cursor, and network requests to VLC.

All public objects should be opaque and reference-counted or have explicit
create/destroy ownership.  Callbacks must never occur while an internal lock is
held.  Parser inputs, script execution, and resource allocation need configurable
limits.  The first implementation may be single-threaded, provided every public
entry point documents that VLC must call it on the navigation thread.

## Work plan

### 0. Preserve evidence and create a conformance harness

**Implementation status:** the opt-in identity/inventory/CRC test, JSON inventory
output, synthetic XML seeds, parser smoke test, fuzz harnesses, and interaction
trace schema are implemented.  A behavioral trace and screenshot hashes still
have to be recorded on a conforming player; they cannot be truthfully inferred
from the archive or generated by the library under test.

* Add an opt-in `reference-menu` CTest that checks the external file's size and
  hash, lists all 40 entries, verifies all CRCs, and emits a machine-readable
  inventory.  Never download the artifact during a normal build or test run.
* Add checked-in, independently generated micro-fixtures for each container
  structure.  Do not derive image or script bytes from the reference artifact.
* Capture expected behavior manually with a conforming HD DVD player: initial
  pixels and focus, every key transition, every button action, timer behavior,
  title/playlist changes, and menu reopening.  Store the trace and hashes of
  reference screenshots, not copyrighted image data.
* Add fuzz targets for the ACA directory, object envelope, URI resolver, XMF,
  XMU/style parser, and script decoder.  Run them with ASan/UBSan and bounded
  memory/time settings.

**Exit criterion:** a reproducible report identifies every referenced resource
and every user-visible state transition, and malformed micro-fixtures fail with a
specific status instead of crashing or reading out of bounds.

### 1. Introduce safe byte streams and HD DVD URI resolution

* Replace path-only reads with a random-access `hddvd_stream` abstraction backed
  by a file, an ACA member, or host callbacks.  Use 64-bit offsets and reads; do
  not load an entire EVO or arbitrary resource by default.
* Represent ACA directory entries dynamically rather than truncating names into
  a fixed 256-byte field.  Validate header fields, integer additions, entry/data
  overlap, duplicate names, padding, flags, ordering, and platform file-size
  limits.  Add zero-copy/ranged member reads and avoid reopening/reparsing the
  archive once per member.
* Implement canonical `file:///dvddisc/...` resolution with percent decoding,
  separator normalization, ASCII case folding appropriate to the disc format,
  dot-segment rejection, and containment checks.  Resolve
  `ADV_OBJ/archived.aca/member` without extracting it to disk.

**Exit criterion:** all manifest references resolve through one API on Linux,
Windows, and macOS; traversal, ambiguous names, and out-of-range reads are
rejected.

### 2. Parse the AACS object envelope

* Specify the observed header variants and object types in an internal format
  note, then implement strict length/version/type/trailer validation.
* Return a payload view plus media type (`XML manifest`, `XML markup`, `PNG`, or
  `HDi script`) and provenance.  Detect media signatures only as a consistency
  check, not as the primary framing rule.
* Keep decryption pluggable.  If a protected object genuinely needs AACS
  decryption, return `HDDVD_EPROTECTED` (a new explicit status) and let VLC's
  legally supplied access/decryption layer provide clear bytes.
* Route `hddvd_xmf_dump`, `hddvd_xmu_dump`, and new resource APIs through this
  parser while retaining support for already-unwrapped data.

**Exit criterion:** all XML and PNG payloads in the reference archive are exposed
at their true payload boundaries, and all four scripts are classified
deterministically without scanning for magic strings.

### 3. Replace diagnostic XML dumping with typed XMF and XMU models

* Add XMF APIs for application id, region, ordered scripts, markup documents, and
  resource roots.  Validate the HD DVD namespaces and preserve unknown optional
  elements for forward compatibility.
* Add XMU parsing for the element tree, ids, style rules/references, namespaced
  state and style attributes, and the title clock.  Implement the cascade needed
  by the fixture, including absolute pixel geometry, `display`, `zIndex`,
  `backgroundImage` lists, `contentWidth/Height=scale-to-fit`, and `navLeft`,
  `navRight`, `navUp`, and `navDown`.
* Resolve ids and resources in a second pass so forward references work.  Reject
  duplicate ids and cycles in styles/navigation, with useful diagnostics.
* Preserve the dump functions as tools built on the typed model, and make
  `hddvd-menuinfo` report envelope, dependency, layout, and unsupported-feature
  information.

**Exit criterion:** the reference scene produces the expected bounds and ordered
normal/focus image candidates for every visible node, with no fixture-specific
filenames in library code.

### 4. Execute HDi scripts

This is the highest-risk milestone and must not be replaced by hard-coded button
behavior.

* Disc scripts are ECMAScript 3 source text (`docs/formats/hdi-script.md`), so
  no binary format has to be decoded.  Run them in a maintained, sandboxable
  ECMAScript engine, as an optional component, with deterministic instruction,
  recursion, heap, timer, and wall-clock budgets.
* Implement the HDi host subset exercised by the trace: DOM lookup and style/state
  mutation, event listener registration and dispatch, focus, key events, timers,
  application lifecycle, title clock access, playlist/title/chapter control, and
  menu open/close.  Inventory calls before implementing them; unsupported calls
  must raise a visible runtime diagnostic rather than becoming no-ops.
* Disable filesystem, process, and unrestricted network access.  Network calls
  go through a host policy callback and default to denied; URI access remains
  confined to disc resources.

**Exit criterion:** scripts drive every captured state transition and playback
command with no filename-, id-, or title-specific branches, under sanitizers and
execution limits.

### 5. Render a deterministic display list

* Decode PNG through a host-supplied decoder or an optional, well-maintained image
  dependency.  Cache by canonical resource identity with explicit byte/pixel
  budgets and validate dimensions before allocation.
* Compute a 1920x1080 logical scene, nested offsets, clipping, scale-to-fit,
  visibility, and stable z-order.  Choose the image-list entry from interaction
  state (normal/focused) as required by HDi semantics.
* Expose premultiplied RGBA image planes and damage-tracked quads, rather than a
  VLC-specific picture type.  Include logical-to-video coordinate transforms for
  letterboxing and mouse hit testing.
* Add pixel tests using original synthetic PNGs plus structural display-list
  checks for the external fixture.  Reference screenshot hashes are diagnostic
  when different color pipelines make exact hashes inappropriate.

**Exit criterion:** the initial menu and each recorded focus/submenu state match
the trace in geometry, resource selection, visibility, and stacking.

### 6. Synchronize navigation with playback

**Implementation status:** the core typed XPL model now represents configuration,
media attributes, titles, typed primary/substitute/secondary presentation clips,
advanced-subtitle segments, chapters, navigation tracks, applications,
resources, scheduled events, pause points, normalized frame times, and validated
title branches. An external-only inventory covers four independently authored
playlists. Chapter entry points are validated in playback order. Application
lifecycle windows are derived from the authored times, the five external playlists are fully modelled, any remaining unmodelled constructs are
reported for the strict external conformance check, and the navigation
scheduler handles pause, rate, seek, discontinuity, title end, and menu
close/reopen. A title time now resolves through the playlist's clips, the time
maps, and the VTI's EVOB table to an EVO file and the sector to read from.
Standard Content IFO tables remain outstanding.

* Add monotonic title-clock updates, pause/rate/seek/discontinuity notifications,
  one-shot and repeating timers, and ordered event queues.  Define whether times
  use 90 kHz ticks or microseconds at every API boundary.
* Finish XPL parsing beyond `find_start_ref`: playlists, clips, title/chapter
  ranges, entry points, application lifecycle, and branching needed by script
  commands.  Complete IFO/MAP semantics needed to map logical title positions to
  EVO byte/time ranges; the existing probes are not playback navigation.
* Expose stream metadata, angle/audio/subtitle selection, and end-of-title events
  without duplicating VLC's elementary-stream decoding.  Harden EVO packet
  parsing across buffer boundaries and malformed PES headers.

**Exit criterion:** every reference-menu playback action maps to an unambiguous
host command, and focus/application state remains correct through pause, seek,
end-of-title, menu close, and reopen.

### 7. Add and validate the VLC integration

* Build a thin VLC module that opens the HD DVD root, supplies decrypted byte
  streams where available, demuxes EVO through VLC, and runs libhddvd navigation
  on a serialized worker.  Convert display-list updates to VLC subpictures and
  VLC key/mouse actions to HDi events.
* Map host commands to VLC input controls and acknowledge success/failure back to
  the runtime.  Do not let callbacks recursively enter libhddvd.
* Define capability negotiation so VLC can report `menu unsupported` with the
  exact missing feature instead of silently falling back.  Keep ABI versioning,
  feature flags, and optional script/image backends explicit in `pkg-config` and
  CMake metadata.
* Test headless navigation with a mock VLC host, then test the real module with
  clear and AACS-protected discs.  Add ThreadSanitizer runs for event/clock races
  and Valgrind/LSan runs for repeated open/close cycles.

**Exit criterion:** an unmodified reference disc can be opened in VLC, all
captured interactions pass, audio/video continue correctly behind the overlay,
and unsupported/protected configurations fail with actionable messages.

### 8. Harden packaging, diagnostics, and release validation

* Continuously build static and shared libraries with the supported compiler and
  operating-system matrix, including sanitizer jobs on untrusted parser inputs.
* Install the library into an isolated prefix and compile clean C and C++
  consumers against the installed CMake package on every tested configuration.
* Stabilize structured diagnostics and consolidate parser, resource, display,
  script, timer, and event limits before declaring the ABI release-ready.

**Exit criterion:** installed-package consumers, sanitizers, ABI checks, and all
configured limits run as automated release gates on every supported platform.

### 9. Add actionable host diagnostics

* Retain structured status, subsystem, resource identity, optional byte offset,
  and human-readable context on long-lived public handles.
* Clear stale diagnostics after successful operations and keep stable status
  strings available for callers that do not need detailed failure information.
* Propagate protected, malformed, missing, ambiguous, and unsupported failures to
  integrations without requiring them to parse log output.

**Exit criterion:** hosts can present the failed subsystem and resource for every
context-bound operation, and tests verify that successful recovery clears the
previous failure.

## Public API shape to stabilize before VLC work

Exact names are subject to review, but the API should cover these concepts:

* `hddvd_disc` and `hddvd_stream` for discovery and bounded resource reads;
* `hddvd_object` for validated envelope metadata and payload views;
* `hddvd_application` for immutable XMF/XMU models;
* `hddvd_player` for lifecycle, input events, clocks, and queued execution;
* `hddvd_host_ops` for playback, resource/decryption, logging, and policy; and
* `hddvd_display_list` for renderer-neutral overlays and hit regions.

Every call must specify ownership, thread affinity, reentrancy, integer units,
error behavior, and ABI availability.  Add queryable feature bits for envelope,
markup, scripts, rendering, navigation, and protection support.  Do not expose
libxml2 nodes, a script engine's values, `FILE *`, or VLC types in the public ABI.

## Test matrix and release gates

Run the following at each milestone:

* GCC and Clang on Linux, MSVC on Windows, and Clang on macOS, both shared and
  static builds;
* 32-bit (where supported) and 64-bit large-file tests;
* ASan/UBSan, ThreadSanitizer for the runtime, static analysis, and format checks;
* unit and property tests for valid/invalid structures, deterministic runtime
  replay tests, and AFL++/libFuzzer corpora containing only synthetic inputs; and
* ABI comparison and install/consumer tests for each release candidate.

The reference-menu test is a release gate when the artifact is supplied by the
maintainer, but remains an ordinary skip for public CI.  A release is not
"supports this menu" until the external conformance report shows zero unknown
object types, XML properties, host calls, resources, or
unacknowledged playback commands along every captured interaction path.

## Risks and deliberate non-goals

* **Specification availability:** the HDi host API specification is not public,
  so host-object behavior may be the critical path.  Base it on what disc
  scripts use (`docs/hdi-host-api.md`) and observed player behavior, and make
  unimplemented calls visible errors rather than guesses.
* **Content protection:** this work must not embed keys or bypass AACS.  The
  library consumes bytes supplied through an authorized host layer and reports
  protected content distinctly.
* **Security:** menus are untrusted programs.  Resource containment, execution
  budgets, network denial, integer-overflow checks, and fuzzing are release
  requirements, not cleanup work.
* **Scope:** full compatibility with every HD DVD is not required for the first
  milestone, but every implementation must be format-driven and extensible.  No
  reference-title ids, filenames, coordinates, or scripted outcomes may appear
  in production code.
* **VLC separation:** libhddvd will not decode VC-1/H.264/audio, own an output
  window, or call VLC internals.  VLC will not run HDi scripts or duplicate the
  menu state machine.
